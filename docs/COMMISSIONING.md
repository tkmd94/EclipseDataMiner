# EclipseDataMiner 臨床コミッショニング手順書 (Clinical Commissioning Guide)

[English](COMMISSIONING.en.md) | **日本語**

本ドキュメントは、Varian Eclipse ESAPI 治療計画データマイニング・スタンドアロンアプリケーション **EclipseDataMiner (v3.0 / Eclipse v15.6 & v16.1 対応)** を施設の臨床・研究運用に投入する前に実施すべき**コミッショニング（受入試験・臨床妥当性検証）の実施基準、検証項目チェックリスト、および安全管理手順**を定めたものです。

> [!NOTE]
> EclipseDataMiner の全機能は **完全 Read-Only 動作** です。患者データベースや治療計画データの変更・保存（`SaveModifications` 等）は一切行いません。安全な読み取り専用アクセスですが、大量の計画を走査するため、必ず本手順書に従ってテスト環境または代表症例データセットにて検証を実施し、施設の医学物理責任者の承認を得て運用を開始してください。

## 1. コミッショニング方針と準拠ガイドライン

EclipseDataMiner のコミッショニングは、以下の標準的医学物理・放射線治療安全ガイドラインに準拠して実施します：

- **AAPM TG-275**: 放射線治療計画における安全管理と独立データ検証手順
- **AAPM TG-263**: 放射線治療における輪郭・線量体積指標の標準的命名規約
- **ESTRO Booklet No. 9**: 治療計画における標的体積（CTV / PTV）およびリスク臓器（OAR）評価ガイドライン
- **AAPM TG-101 / ICRU Report 83**: 高精度放射線治療における線量処方・DVH 統計評価基準

### 基本方針
1. **真値との厳密一致**: Eclipse 画面上の DVH 統計ウィンドウに表示される数値（Volume, Max dose, Mean dose, Min dose, D95%, V20Gy 等）と、本ツールで抽出された数値が完全に一致することを確認（許容誤差 $\le 0.01\text{ Gy}$ / $0.01\text{ cc}$ / $0.01\%$）。
2. **処方総線量による正規化整合性**: 相対線量指標（例: V70% 等）の計算基準がプランの処方総線量（`TotalDose`）と厳密に一致することを確認。
3. **無停止・メモリ安全性**: 1,000 件以上の連続計画走査において、UI がフリーズせず、メモリリーク（Working Set の異常肥大）が発生しないことを実機で確認。
4. **患者個人情報の完全保護**: 匿名化モード有効時に、出力ファイル（CSV / JSONL）から生患者 ID、生年月日、承認者氏名が完全に排除されていることを確認。

## 3. カテゴリ別検証チェックリスト

### 3.1 検索フィルタリング精度テスト
- [ ] **複数 ID 検索**: カンマ区切り（例: `ID001, ID002`）で指定した患者が漏れなく抽出されること。
- [ ] **グローバル論理切替 (AND / OR)**:
  - `AND` 選択時: 全条件（線量、分割回数、承認状態等）を満たす計画のみが抽出されること。
  - `OR` 選択時: いずれかの条件を満たす計画が抽出されること。
- [ ] **承認状態フィルタ**: `Unapproved`, `Plan approved`, `TRT approved` の選択が正しく反映されること。
- [ ] **合算計画 (PlanSum)**:
  - 「Include PlanSum」OFF 時: 単一計画 (`PlanSetup`) のみが対象となること。
  - 「Include PlanSum」ON 時: 合算計画 (`PlanSum`) も漏れなく抽出され、不在項目（ビーム情報等）が `N/A` で安全に埋められること。

### 3.2 輪郭事前スキャン (Pre-Scan) ＆ エイリアス統合テスト
- [ ] **高速事前スキャン**: 対象計画内の全 `Structure.Id` が漏れなくリストアップされ、ヒット件数（MatchedCount）が集計されること。
- [ ] **完全一致 (Exact)**: `PTV-PROST` 等の完全一致マッピングが正しくエイリアスに統合されること。
- [ ] **部分一致 (Contains)**: `prost` 等の部分一致により複数の表記揺れが統合されること。
- [ ] **正規表現 (Regex)**: `PTV.*|ptv.*` により大文字小文字・サフィックス付き輪郭が単一の `PTV` カラムに集約されること。
- [ ] **オプトアウト (除外)**: チェックを外した輪郭（例: `BODY`, `CouchInterior`）が抽出から完全に除外されること。
- [ ] **JSON 永続化**: `Save Rules (JSON)` / `Load Rules (JSON)` によりルールが完全再現されること（`Templates/StructureMapping_Prostate.json` の動作確認含む）。

### 3.3 基本 DVH 統計量 ＆ 線量正規化の検証
- [ ] **単位自動正規化 (Gy統一)**: ESAPI の内部単位が `cGy` の場合でも、出力 CSV / JSONL ではすべて `Gy` に統一されていること。
- [ ] **4大基本統計量の常時自動出力**: 全対象輪郭について、個別の DQP 登録なしに以下の 4 列が正しく出力されること：
  - `<Structure>-Volume[cc]`: Eclipse 輪郭体積と一致（許容誤差 $\le 0.01\text{ cc}$）
  - `<Structure>-Max dose[Gy]`: Eclipse DVH 統計の Max Dose と一致（許容誤差 $\le 0.01\text{ Gy}$）
  - `<Structure>-Mean dose[Gy]`: Eclipse DVH 統計の Mean Dose と一致（許容誤差 $\le 0.01\text{ Gy}$）
  - `<Structure>-Min dose[Gy]`: Eclipse DVH 統計の Min Dose と一致（許容誤差 $\le 0.01\text{ Gy}$）

### 3.4 動的 DQP の計算精度検証
- [ ] **Dose at Volume (D)**:
  - `D95%[Gy]`: 95% 体積線量が Eclipse 表示値と一致すること。
  - `D0.1cc[Gy]`: 絶対体積 0.1 cc の線量が Eclipse 表示値と一致すること。
  - `D95%[%]`: 相対出力指定時、パーセンテージで正しく出力されること。
- [ ] **Volume at Dose (V)**:
  - `V20Gy[%]`: 20 Gy 照射体積割合が Eclipse 表示値と一致すること。
  - `V40Gy[cc]`: 絶対体積 cc で正しく出力されること。
  - `V70%[%]`: 処方総線量（`TotalDose`）の 70% に対する体積割合が正しく算出されること。
- [ ] **Dose Complement (DC) ＆ Complement Volume (CV)**:
  - 補集合体積に対する線量および指定線量未満の補集合体積が正確に計算されること。
- [ ] **DQP CSV テンプレート**: `Templates/DQPlist_Prostate.csv` がエラーなくロードされ、期待通りの列が出力されること。

### 3.5 照射パラメータ・プラン複雑度の検証
- [ ] **Beam MU**: 全照射野の MU 値が `B1:145.2;B2:138.6` の形式で正しく連結出力されること。
- [ ] **Machine / Energy / Technique**: 装置名、エネルギー（6X, 10X 等）、照射技法（ARC, STATIC 等）、MLCタイプ（VMAT, STATIC 等）が正確に出力されること。
- [ ] **Modulation Complexity Score (MCS) / Edge Metric (EM)**: 計算オプション有効時、VMAT / IMRT プランの複雑度指標が正しく出力されること。
- [ ] **計算ログ (Calculation Log)**: アルゴリズム計算ログ内の改行コードがスペースに置換され、CSV 構造を破壊しないこと。

### 3.6 プライバシー保護・患者データ匿名化検証
- [ ] **Patient ID ハッシュ化**: 患者 ID が不可逆な SHA-256 ハッシュ値（64 文字の 16 進文字列）に置換されること。同一患者 ID は常に同一のハッシュ値に変換されること。
- [ ] **個人情報マスキング**: 生年月日（DateOfBirth）および承認者氏名（PlanningApprover）が `REDACTED` にマスクされ、個人が特定できないこと。

### 3.7 ストリーミング出力パイプライン ＆ JSONL 同時出力の検証
- [ ] **1プラン即時フラッシュ**: 抽出が完了したプランごとに CSV / JSONL ファイルへ即座に書き出され、ファイルサイズがリアルタイムに増加すること。
- [ ] **JSON Lines フォーマット**: 出力された `.jsonl` ファイルが標準的な JSON パーサー（Python `json.loads` 等）で 1 行ずつ正常に読み込めること。

## 4. 耐久性・フェイルセーフ・異常系耐性テスト

- [ ] **大量計画連続走査**: 1,000 件以上の計画を連続抽出した際、プロセス（`EclipseDataMiner.exe`）のメモリ使用量が一定（200MB以下）で安定推移し、Out of Memory が発生しないこと（200件ごとの GC 動作確認）。
- [ ] **協調キャンセル動作**: 抽出処理の途中で **「⏹ Cancel」** ボタンを押下した際、即座に安全に中断され、そこまでに抽出されたデータが破損なく CSV に保存されていること。
- [ ] **欠損データ耐性**:
  - 線量未計算のプラン
  - 輪郭セット（StructureSet）が存在しないプラン
  - 最適化設定（OptimizationSetup）が存在しない 3D-CRT プラン  
  上記のような不完全データが含まれていてもクラッシュせず、該当項目に `N/A` を出力して次の計画へスキップ・継続できること。
- [ ] **ファイルロック検知**: 出力先 CSV ファイルが Excel 等で開かれていて書き込めない場合、分かりやすいエラーメッセージを表示してクラッシュを回避すること。
